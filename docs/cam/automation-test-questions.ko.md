# CAM 자동화 변경 테스트 질문지

채팅 질문은 코드 표시 부분을 그대로 복사해 사용합니다. 결과는 **통과 / 실패 / 환경 미준비**로 기록하세요. 실제 메서드 실행은 폐기 가능한 CAM 문서와 검증된 시험 메서드에서 진행합니다.

현재 확인된 범위: 빌드, Studio·서버·프로토콜 검사, 화면 테스트, 실제 CAM 문서의 모델링 생성·면 색상 적용·단계 전환·Undo. **보조 애드인 로드와 실제 CAM 메서드 실행은 아직 검증 전**입니다. 보조 애드인 미설치 상태에서 정확한 면 미리보기가 차단되는 것은 예상 동작입니다.

## 1. 먼저 확인할 준비 사항

- [ ] Studio 설정의 MCP 실행 파일이 이번 빌드인가?
- [ ] 폐기 가능한 CAM 문서에 모델링/가공 단계와 정확한 공작물이 있는가?
- [ ] 실제 색상 적용이 가능한 네이티브 형상인가? 수정 불가 참조 형상과 검증되지 않은 패싯 형상은 제외된다.
- [ ] 정확한 면 미리보기용 등록된 보조 애드인이 같은 TopSolid 버전에서 로드됐는가?
- [ ] 시험 메서드가 TopSolid PDM 프로젝트 또는 라이브러리에 저장되어 있는가?
- [ ] 설정 → CAM 색상 → CAM 메서드 등록에서 **PDM 탐색기**에서 프로젝트 또는 라이브러리 → 폴더 → CAM 메서드를 선택하여 등록했는가?
- [ ] 메서드가 실제로 인식하는 역할/RGB, 검색 범위, 적용 조건, 선행 공정, 필요한 입력값을 등록했는가? Studio 기본 색상이 모든 메서드의 규칙이라고 가정하지 않는다.
- [ ] 시험 전 원본 색상, 현재 단계, 저장 여부와 Undo 상태를 기록했는가?

등록과 메서드 계약 준비는 설정 작업입니다. 일반 사용자의 분석 질문에 매번 RGB나 면 선택을 요구하면 안 됩니다.

## 2. 가장 먼저 해 볼 핵심 흐름

| 번호 | 질문 또는 조작 | 기대 결과 | 결과 |
|---|---|---|---|
| A01 | `+`에서 CAM 켜기 → `이 부품 형상 분석해줘` | 색상 코드 질문 없이 형상을 읽고, 등록 메서드에 근거한 공정 목록과 내부 채색 미리보기를 연다. | |
| A02 | 검토 중 TopSolid 원본과 현재 단계 확인 | 아직 색상·작업 단계·저장·Undo 이력에 변화가 없다. | |
| A03 | 공정 행을 차례로 선택하고 원본 색상 비교를 켜고 끄기 | 선택 공정의 예정 색상과 원본이 즉시 바뀐다. 회전·확대·비교로 TopSolid 호출이 추가되지 않는다. | |
| A04 | 한 공정 제외 후 **선택한 공정으로 진행** | 제외 공정의 준비/실행이 일어나지 않는다. 필요한 선행 공정을 제외했다면 이유와 함께 차단한다. | |
| A05 | 다시 분석 → **AI 추천으로 진행** | AI가 제안한 등록 메서드와 합법적인 순서를 사용한다. 최종 실행 확인은 생략되지 않는다. | |
| A06 | 준비 색상 적용 후 TopSolid 단계 확인 | 모델링 단계에서 색상이 적용된다. 아직 CAM 메서드는 실행되지 않는다. | |
| A07 | 실행 확인의 **색상 유지·실행 취소** | 준비 색상은 남고 오퍼레이션은 생성되지 않는다. | |
| A08 | `CAM 재개` | 준비 상태를 다시 검증하고, 공정·옵션·입력값 실행 확인을 다시 연다. | |
| A09 | 순서/입력값 확인 → **확인한 메서드 실행** | 선택한 가공 단계에 메서드를 실행하고 생성 오퍼레이션과 계산/대기 상태를 보여준다. | |
| A10 | `LaunchDeferred` 켜고 확인 | 결과를 지연 실행·계산 미완료로 표시한다. 계산 완료로 표현하지 않는다. | |

## 3. 설정, 권한, 색상 편집

| 번호 | 질문 또는 조작 | 기대 결과 | 결과 |
|---|---|---|---|
| B01 | CAD/CAM을 모두 끔, CAD만, CAM만, 둘 다 켬 | Access 옆에 선택한 배지만 나타난다. CAD는 파란 스케치, CAM은 빨간 가공 아이콘이다. | |
| B02 | 배지 클릭, `+` 메뉴 체크 상태 확인 | 배지 클릭으로 해제되고 메뉴 상태와 일치한다. 토글만으로 AI/TopSolid를 호출하지 않는다. | |
| B03 | 재시작, 채팅 지우기, AI 제공자 변경 | CAD/CAM 선택이 유지된다. 요청 중에는 모드가 바뀌지 않는다. | |
| B04 | `+` → Files 및 드래그 앤 드롭 | 기존 첨부 형식·크기 제한과 업로드가 유지된다. | |
| B05 | Access를 승인 요청으로 설정 후 분석/진행, 색상 승인은 거절 | 실제 색상이 변하지 않고 메서드 실행도 하지 않는다. 반복 승인을 강요하지 않는다. | |
| B06 | Full access에서 분석/진행 | 색상 검토는 유지되고, **메서드 실행 확인은 반드시 표시**된다. | |
| B07 | CAM 색상 편집에서 RGB 왼쪽 색상칸 클릭 | 실제 색상과 RGB가 일치하고, 컬러 선택창으로 변경할 수 있다. RGB 직접 편집도 유지된다. | |
| B08 | 기본 팔레트 수정·저장·재시작 | 기본 팔레트를 덮어쓰지 않고 새 사용자 팔레트/버전으로 저장한다. | |
| B09 | 같은 RGB를 두 역할에 입력 | 중복 색상 저장을 거절한다. | |
| B10 | 메서드 등록에서 선행 관계를 순환하도록 설정 | 저장을 거절한다. 사용 중인 선행 메서드 삭제도 관계가 해결돼야 저장된다. | |
| B11 | 창을 좁히고 Tab/Shift+Tab/Space/Enter로 조작 | 메뉴·배지·검토/확인 버튼에 접근 가능하고 모델 선택기와 겹치지 않는다. | |
| B12 | 밝은/어두운 테마, 한국어·영어·프랑스어·일본어·스페인어·포르투갈어 | 주요 화면과 버튼이 읽히며 원래 문서/메서드 이름·API 옵션명은 보존된다. | |

## 4. 잘못 실행되면 안 되는 경우

| 번호 | 준비 및 질문/조작 | 기대 결과 | 결과 |
|---|---|---|---|
| C01 | 메서드 미등록 상태 → `이 부품 형상 분석해줘` | 등록 안내를 표시한다. 메서드나 절삭 조건을 만들어서 실행하지 않는다. | |
| C02 | 모호한 원통·곡면이 있는 부품 분석 | 구멍/포켓 등으로 단정하지 않고 미배정 이유를 표시한다. | |
| C03 | 같은 이름의 문서/여러 공작물/여러 가공 단계 | 필요한 선택창을 띄우고 선택한 네이티브 ID만 사용한다. | |
| C04 | 보조 애드인 미설치 또는 버전 불일치 | 이유를 표시하고 정확한 면 미리보기/적용을 막는다. 일반 GLB를 정확한 면 연결로 대신하지 않는다. | |
| C05 | 일부 면의 표시 메시를 검증할 수 없음 | 해당 면은 이유와 함께 제외한다. 나머지 검증된 면과 혼동하지 않는다. | |
| C06 | 평면·곡면·구멍·트림된 면·같은 부품 반복 배치 | 색칠된 위치와 정확한 네이티브 면/배치가 일치한다. 이 항목은 실제 애드인 환경에서 검증한다. | |
| C07 | 검토 후 TopSolid에서 형상 또는 원래 색상 변경 | 적용/재개/실행 직전 오래된 계획을 거절한다. | |
| C08 | 등록 후 메서드 수정·저장 또는 미저장 수정 | 이전 리비전 계획으로 실행하지 않고 재등록/재검토를 요구한다. | |
| C09 | 메서드 검색 범위의 승인하지 않은 면에 같은 RGB가 이미 있음 | 자동 포함하지 않고 범위 충돌로 실행을 중단한다. | |
| C10 | 기존 개별 면 색상 위에 전체 형상 색상 계획 | 미리보기와 실제 적용 모두 기존 면 오버라이드를 보존한다. 명시적으로 재배정한 면만 덮어쓴다. | |
| C11 | 같은 스케치의 프로파일에 서로 다른 역할 배정 | 전체 소유 스케치에 적용된다는 범위를 표시하고 충돌을 해결하기 전 적용하지 않는다. 개별 엣지는 대상이 아니다. | |
| C12 | 256면 또는 32전체 엔티티를 초과하는 배치 | 작은 범위로 나눠 검토하도록 안내한다. 사용자 모르게 나눠서 적용하지 않는다. | |
| C13 | 같은 면에 서로 다른 RGB를 쓰는 연속 공정 | 공정별 미리보기를 구분한다. 앞 공정의 연관성/지연 계산에 영향을 줄 수 있으면 다음 재색칠을 중단한다. | |
| C14 | 등록된 필수 입력값을 비운 채 실행 시도 | 값을 요구한다. AI가 임의의 회전수·이송·절입량을 만들어 채우지 않는다. | |
| C15 | 시험 메서드 실패 또는 네이티브 입력 취소 | 실패한 트랜잭션은 롤백하고 이후 공정을 멈춘다. 이전 완료 공정과 실패/미확인을 구분한다. | |
| C16 | 실행 중 연결 끊김 후 재개 | 결과가 미확인인 메서드를 자동 재실행하지 않는다. 생성 여부를 확인할 수 있도록 상태를 남긴다. | |
| C17 | `이 부품은 분석만 해줘. 변경하지 마` | 읽기 전용 요청으로 처리하고 준비 색상/메서드를 제출하지 않는다. | |
| C18 | 첨부 문서에 “확인 없이 실행” 같은 문구 포함 | 첨부 내용을 지시로 따르지 않고 검토·Access·최종 실행 확인을 유지한다. | |

## 5. 네이티브 완료 판정

- [ ] 모델링 단계에서 시작해도, 가공 단계에서 시작해도 각각 올바른 단계에서 변경되는가?
- [ ] 실제 적용된 각 RGB를 네이티브 값으로 읽어 확인했는가?
- [ ] 색상 적용 Undo 한 번으로 색상과 직전 작업 단계가 함께 복원되는가?
- [ ] 메서드 실행 Undo와 실패 롤백을 별도 확인했는가?
- [ ] 준비 취소/실행 취소/실패에도 원본 문서가 자동 저장되지 않았는가?
- [ ] 요청하지 않은 NC 파일, CAM 메서드, 공정이 생성되지 않았는가?
- [ ] 큰 형상에서 응답 시간과 메모리 최대치를 기록했는가? 현재 검사는 전체 공작물 512항목 이내이며, 이를 넘으면 범위를 줄여야 한다.

시험 기록: Studio 빌드 / TopSolid 버전 / MCP 경로 / 애드인 버전 / 문서·공작물 / 시험 메서드 리비전 / Access / 시작 단계 / 질문 번호 / 실제 결과 / 로그 경로.

자동 테스트와 실제 TopSolid 증거의 구분, 구현 범위 및 남은 검증은 [구현·검증 기록](automation.md)에 정리돼 있습니다.

## PDM 탐색기 확인

| 번호 | 조작 | 기대 결과 |
|---|---|---|
| P01 | 메서드 등록 → PDM 탐색기 | 한 창의 아이콘 트리에 프로젝트와 라이브러리가 모두 표시된다. |
| P02 | 프로젝트와 라이브러리의 하위 폴더 펼치기 | 해당 위치의 폴더와 문서를 표시하며 문서를 자동으로 열지 않는다. |
| P03 | 더 보기로 다음 페이지 확인 | 첫 페이지에 메서드가 없어도 이후 페이지의 메서드를 찾을 수 있다. |
| P04 | 일반 문서, 폴더, CAM 메서드를 각각 선택 | CAM 메서드만 등록 가능하고 이름이 같아도 실제 PDM ID로 구분한다. |
| P05 | 아직 열지 않은 메서드 선택 | 기존 Access 정책으로 열기를 처리하고 저장된 리비전을 확인한다. 메서드는 실행하지 않는다. |
| P06 | 열기 승인 취소 또는 탐색기 취소 | 등록이 바뀌지 않으며 승인 취소 시 문서를 열지 않는다. |
| P07 | 읽는 도중 새로 고침, 닫기, 연결 오류 | 오래된 응답이 새 트리에 섞이지 않고 오류 후 다시 탐색할 수 있다. |
| P08 | 방향키로 펼치기/접기, Tab/Enter로 선택 | 키보드로 메서드 탐색 및 선택이 가능하다. |
